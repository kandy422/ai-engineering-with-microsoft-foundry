# Module 8 · Choose and adapt a model

Run the commands from this module directory. Install the .NET SDK 10.0.403 and use PowerShell 7 on Windows x64. Only the managed fine-tuning lab needs Python 3.12.10 and a Foundry account. Build with `dotnet build lab/SupportLab.csproj`.

For the local model lessons, unpack the Windows x64 CPU build of [llama.cpp b12287](https://github.com/ggml-org/llama.cpp/releases/tag/b12287) into `tools/llama`. Keep the included DLLs next to the executable. Download the pinned [Qwen 0.5B GGUF](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF/resolve/9217f5db79a29953eb74d5343926648285ec7e67/qwen2.5-0.5b-instruct-q4_k_m.gguf) and [Qwen 1.5B GGUF](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/resolve/91cad51170dc346986eccefdc2dd33a9da36ead9/qwen2.5-1.5b-instruct-q4_k_m.gguf), save them as `tools/models/qwen-0.5.gguf` and `tools/models/qwen-1.5.gguf`, and verify SHA-256 against the manifest. Use the loopback server on port 8408. The benchmark script stops it after each run.

For an independent exercise, copy `lab/benchmark.json` to `lab/benchmark-extra.json`. Add a new fictional ticket about a refund for an order that already arrived. Decide which queue owns the requested action and write its expected label before running either model. In one terminal, run `tools/llama/llama-server.exe -m tools/models/qwen-0.5.gguf --host 127.0.0.1 --port 8408 -c 2048 -t 4 -ngl 0 -np 1 --alias qwen-0.5`. In a second terminal run `dotnet run --project lab -- benchmark lab/benchmark-extra.json http://127.0.0.1:8408/ qwen-0.5 3`. Stop the server and repeat with the 1.5 model and alias. Explain whether the extra case changes your choice under your own latency and exact-match requirements. Keep it out of training and validation.
