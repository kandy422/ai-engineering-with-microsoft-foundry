AI Engineering with Microsoft Foundry

Build a ticket classifier, generate constrained replies, retrieve policy evidence, add scoped tools, evaluate changes and deploy a support assistant.

All 16 module packages are included. Begin with the local setup, then use each module guide for its prerequisites and checkpoints. Instructor cloud recordings and learner-run commands are clearly distinguished.

Start with lesson 1.5

  1. Extract the course ZIP to a writable folder such as D:\AI-Course. Open this page from the extracted folder.
  2. Install the required runtimes listed in each module: Windows PowerShell 7, Python 3.12 for ML labs, and .NET 10 SDK for applications. Each module pins its tested dependencies and provides verification commands.
  3. Open Module 1 learner setup. Run the local starter and verify HTTP 200, 404 and 400 before changing code.
  4. For each lesson, predict the result, run the baseline, make the named change, inspect the output and complete the independent exercise. Use the provided completed checkpoint to diagnose differences.

Local work and cloud work

Modules 2–4 run local Python experiments. Other modules distinguish local tests, saved instructor responses and optional live Foundry requests. A recorded response is evidence of an instructor run; it is not a new cloud request from your machine.

Live exercises require your own authorized Azure subscription, supported regional resources and Entra permissions. Follow the module's exact setup, cost controls and cleanup. Course resource addresses in recorded evidence are historical and are not learner credentials. Never place API keys or access tokens in source files.

Check your learning

Do not use a successful HTTP call or a toy accuracy score as proof of production quality. Keep held-out cases, inspect evidence and failures, and compare the same cases before and after a change. The final capstone includes authenticated scope, durable approval, traces, deployment and rollback.
